# qux/templatetags

Two template tag libraries, loaded together in any template:

```django
{% load qux quxform %}
```

## `qux.py` — generic template helpers

Filters and tags for everyday template work: numeric formatting, date manipulation, URL-querystring helpers, static-file existence checks, dictionary access by key, conditional CSS class injection, etc. Loaded via `{% load qux %}`.

Common ones (see source for the full list):

- `{{ value|multiply:other }}` — multiply two values; returns None on TypeError.
- `{{ items|get:key }}` — dict lookup that doesn't crash on missing key.
- `{% qux_static_exists "path/to/file.svg" %}` — True if the file resolves through Django's staticfiles finders. Useful for "use the project's logo if present, fallback otherwise" templates.

## `quxform.py` — form-rendering helpers

Helpers for laying out forms generated by `qux.utils.forms.QuxForm` / `QuxModelForm` (which auto-apply Bootstrap CSS classes to widgets). Covers field-row rendering, label-classes, error display, etc. Loaded via `{% load quxform %}`.

## When to use, when to skip

These are convenience helpers, not architectural primitives. If a project already has its own templatetag library (most non-trivial Django projects do), skip these and use the project's. The qux library exists for downstream apps that bootstrap from the qjango template and want sane defaults out of the box.

Tests live at `src/qux/tests/test_templatetags.py`.
